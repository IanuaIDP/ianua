Ianua is configured only through environment variables. Each process reads them once, when it starts, and checks them all before anything runs.

- **Unset or blank** means the default in the tables below. A setting with no default, marked **required**, stops the process when it is missing.
- **A wrong value stops the process**, with a message naming the variable. A typo is never quietly replaced by the default. A number outside its range is refused the same way.
- **Units are in the name.** `_SECONDS`, `_MS`, `_MINUTES`, `_HOURS`, `_DAYS`, `_BYTES` and `_KIB` say what the number means.
- **Addresses hold no user or password.** A URL setting with a credential in it is refused, since the address is printed with the configuration. Credentials have settings of their own. A refused address is never repeated in the message.
- **On or off** settings take `true`, `1`, `yes` or `on`, and `false`, `0`, `no` or `off`. Choices, such as `MODE`, match in any case.
- **Lists** are comma-separated. Blank entries are dropped.
- A `.env` file in the working directory is read too. A variable the process was given wins over the file's.
- At start the server logs the names of the settings that were set. It never logs their values.

## Secrets in files

Every secret can be given in its variable, or as a file. Set `NAME_FILE` to the path of a file holding the value, for secrets mounted by Kubernetes or Docker. One trailing line break is dropped. Setting both `NAME` and `NAME_FILE` is refused, and so is an empty file.

These take a `_FILE` variant: `DATABASE_URL`, `MIGRATION_DATABASE_URL`, `AUDIT_PURGE_DATABASE_URL`, `GATEWAY_DATABASE_URL`, `NAMESERVER_DATABASE_URL`, `HMAC_SECRET`, `EVENT_SIGNING_SECRET`, `ENCRYPTION_KEY`, `ENCRYPTION_RETIRED_KEYS`, `CACHE_URL`, `BUS_TOKEN`, `FILES_OBJECTS_SECRET_ACCESS_KEY`, `SMTP_PASSWORD`, `SENDGRID_API_KEY`, `POSTMARK_SERVER_TOKEN`, `MAILGUN_API_KEY`, `SES_SECRET_ACCESS_KEY`, `TWILIO_AUTH_TOKEN`, `TWILIO_API_KEY_SECRET`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `TURNSTILE_SECRET_KEY`, `AGENT_INTENT_EMBEDDING_API_KEY`, `CLOUD_AWS_SECRET_ACCESS_KEY`, `CLOUD_AWS_SESSION_TOKEN`, `INSTALL_OWNER_PASSWORD` and `OPERATOR_PASSWORD`. The gateway's `VAULT_TOKEN` and `LOG_SINK_AUTH` take one too, and so does the agent runner's `RUNNER_KEY`.

No refusal ever repeats a secret's value.

## Setting them

**With Helm.** The chart sets the common variables from its own values (`config.baseDomain`, `config.email`, `secrets.*` and so on). Anything else goes under `config.env`, by variable name. Every component gets it:

```yaml
config:
  env:
    MFA_LOCKOUT_SECONDS: "1800"
    GATEWAY_MAX_CONNECTIONS: "20000"
```

Don't repeat a variable the chart already sets from another value. The chart refuses to render if you do.

**Anywhere else** (Docker, systemd, a shell), set them as normal environment variables.

## Commands and modes

The `ianua` binary runs one command. With none it serves.

| Command | What it does | What it reads |
| --- | --- | --- |
| `ianua` or `ianua serve` | Serves the API, runs the worker, or both, as `MODE` says. | Everything |
| `ianua migrate` | Brings the schema up to date as the database owner, makes the app's and the audit purge's roles, and the gateway's and the nameservers' where their logins are set, and exits. | `APP_ENV`, the logging settings and the database settings only |
| `ianua install` | Makes a self-hosted installation's organization, first tenant and owner, then exits. | Everything, and the `INSTALL_*` settings |
| `ianua operator create --email <address>` | Makes the platform's first operator, then exits. | Everything, and `OPERATOR_PASSWORD` |
| `ianua demo` | Seeds a demonstration organization, then exits. Development only. | Everything |
| `ianua link-pki --server-name <host> --nameservers <ns1,ns2> --out <folder>` | Issues the private authority, the listener's certificate and one certificate per nameserver for the [nameserver link](#domains-and-certificates), writes them to the folder, and exits. Refuses to write over any of them. | Nothing |
| `ianua internal-pki --gateway-name <host> --api-name <host> --out <folder>` | Issues the internal authority, the certificates of the gateway's workflow and runner listeners for the name the worker and runners dial it by, the certificate of the API's relay listener for the name the gateway dials it by, and the worker's and the gateway's certificates, writes them to the folder, prints the settings the gateway, the API and the worker take, and exits. Refuses to write over any of them. | Nothing |
| `ianua connector-pki --listener-names <host,...> --out <folder>` | Issues the connector authority and the certificate of the gateway's connector listener for the names connectors dial it by, writes them to the folder, prints the settings each side takes, and exits. Refuses to write over any of them. See [Connectors](#connectors). | Nothing |

`MODE` picks what `serve` runs: `api`, `worker` or `all` (the default). Every command but `migrate` reads and checks every setting, whatever `MODE` says, except the two only one command reads: `INSTALL_*` and `OPERATOR_PASSWORD`. A setting only matters where its part runs:

- **API nodes** (`api`, `all`) use the public listener, sign-in, the [LDAP directory](#ldap-directory) and the rest of the API's settings.
- **Worker nodes** (`worker`, `all`) use the [worker](#worker) settings, and migrate as they start.
- **Every node** uses the database, the keys, the bus, the cache, the file store and the internal listener, which answers `/health/live`, `/health/ready` and `/metrics` on every node. Every node's probes go to `INTERNAL_PORT`; the public listener serves no probe.

## Start-up checks

Besides each value on its own, the server checks the settings against each other and against the command. Each of these stops it with a message naming the setting:

- **Privileged logins.** The worker (`MODE=worker` or `all`) and the `migrate`, `install` and `operator create` commands need both `MIGRATION_DATABASE_URL` and `AUDIT_PURGE_DATABASE_URL`. A node serving `MODE=api` must hold neither: the server refuses to start an API node with either set.
- **Roles apart.** `DATABASE_URL`, `MIGRATION_DATABASE_URL` and `AUDIT_PURGE_DATABASE_URL` must sign in as three different roles, `GATEWAY_DATABASE_URL`, where set, as a fourth, and `NAMESERVER_DATABASE_URL`, where set, as a fifth. An API node must not hold `GATEWAY_DATABASE_URL` or `NAMESERVER_DATABASE_URL` either.
- **Shared bus and cache.** A split deployment (`MODE=api` or `worker`) needs `BUS_URL` and `CACHE_URL`, so the nodes share events, counts and cache versions. `BUS_URL` without `CACHE_URL` is refused too.
- **Two roots.** `EVENT_SIGNING_SECRET` must not be the same key as `HMAC_SECRET`, in any spelling.
- **Certificate orders.** On worker nodes, `JOB_TLS_TIMEOUT_SECONDS` must be longer than `ACME_DNS_PROPAGATION_TIMEOUT_SECONDS`, or every order over DNS would be stopped while it still waits.
- **Event waits.** `WORKER_EVENT_RETRY_DELAY_SECONDS` must be shorter than `WORKER_EVENT_ACK_WAIT_SECONDS`.
- **Command fits the deployment.** `ianua demo` is refused when `APP_ENV` is production. `ianua install` is refused unless `DEPLOYMENT=self_hosted`.
- **Settings nothing would read.** These are refused rather than ignored, so nobody believes they did something:
  - `INSTALL_*` for `serve`, `operator create` and `demo`.
  - `TRUSTED_DOMAINS` without `DEPLOYMENT=self_hosted`.
  - `OPERATOR_PASSWORD` for `serve`, `install` and `demo`.
  - Another mail provider's settings than `EMAIL_PROVIDER` names, and any provider's settings with `none`.
  - `FILES_OBJECTS_*` with `FILES_STORE=disk`, and `FILES_DIR` with `objects`.
  - `BUS_TOKEN` or `BUS_CREDENTIALS_FILE` without `BUS_URL`.
  - `ACME_CONTACT_EMAIL` without `ACME_DIRECTORY_URL`.
  - The `GRPC_*` files without `GRPC_LISTEN`, `GRPC_LISTEN` on a worker node, and the LDAP certificate or `LDAP_TLS_TERMINATED_UPSTREAM` without `LDAP_BIND_ADDR`.
  - Agent attestation settings for an attestation `AGENT_ATTESTATION_ALLOWLIST` does not list, and embedding settings without `AGENT_INTENT_EMBEDDING_URL`.
- **Half a set.** A provider's settings come whole or not at all: Stripe needs its key and its signing secret; Twilio needs an account, one way to sign in and one sender; the AWS keys need both halves; Turnstile needs its secret and its hostnames; SMTP takes a username and a password together; a certificate and its key come together.
- **Unsafe in production.** `SMTP_TLS=none`, a plain `http` `TWILIO_API_URL` or `PASSWORD_BREACH_URL`, a plain LDAP directory, `OUTBOUND_DELIVERY_CA_FILE`, and a site with a port in `JIRA_SITES` or `SALESFORCE_SITES` are refused when `APP_ENV` is production. Without ACME or upstream TLS termination, custom domains require uploaded certificates.

## Deployment

| Variable | Default | What it does |
| --- | --- | --- |
| `APP_ENV` | `production` | `production` or `development` (also `prod`, `dev`). Development puts internal error chains in answers and relaxes the checks meant for production, so it is asked for by name. |
| `MODE` | `all` | `api`, `worker` or `all`. See [Commands and modes](#commands-and-modes). |
| `DEPLOYMENT` | `cloud` | `cloud`, the hosted service, or `self_hosted` (also `self-hosted`), one organization's own installation. |
| `APP_BASE_URL` | **required** | The dashboard's public `https` address. Emailed links and identity providers point here. File download links and tenants' logos are made under it too, at `{APP_BASE_URL}/api/v1/files/...`, so whatever serves this address must send `/api/v1` to the API. |
| `PROXY_BASE_DOMAIN` | **required** | The domain tenants' platform subdomains sit under. |
| `PLATFORM_ADDRESSING` | chosen from TLS settings | `off`, `flat` or `nested`. Self-hosted installations with an operator wildcard default to `flat`, with apps at `wiki-k7f3q9.apps.example.com`. Cloud deployments with ACME, nameservers and a proxy address default to `nested`, at `wiki.k7f3q9.apps.example.com`. Otherwise platform addresses are off and startup reports custom domains only. |
| `PLATFORM_WILDCARD_TLS` | `false` | Confirms the operator supplies a certificate covering `*.PROXY_BASE_DOMAIN`. Required for `flat`; the operator obtains and renews it with their own tooling. |
| `PLATFORM_HOSTS` | empty | Additional deployment hostnames, comma-separated. Their first labels are reserved against organization slugs, alongside configured public URLs, nameservers, the apps domain and `app`, `api`, `www`, `ns1`, `ns2`. The Helm chart includes its ingress and Traefik hosts. Sixteen-character hexadecimal slugs are also reserved for random tenant labels. |
| `EMAIL_LOGO_URL` | `https://api.ianua.io/email-logo.png` | The logo shown in mail. |
| `OAUTH_DEVICE_VERIFICATION_URI` | `{APP_BASE_URL}/device` | Where the device sign-in flow sends a person to type their code. |
| `TRUSTED_DOMAINS` | empty | Parent domains whose names tenants may use without a DNS proof. Only with `DEPLOYMENT=self_hosted`: on a shared deployment it would let any tenant claim any name beneath them. |

### Self-hosted installation

Read by `ianua install` alone, which makes the organization from them and runs only with `DEPLOYMENT=self_hosted`. Every other command refuses them, so give them to the install run only: the owner's first password never stays in a server's environment. Changing them after the install changes nothing.

| Variable | Default | What it does |
| --- | --- | --- |
| `INSTALL_ORGANIZATION_NAME` | **required** | Name of the one organization. |
| `INSTALL_TENANT_NAME` | `Main` | Name of its first tenant. |
| `INSTALL_OWNER_EMAIL` | **required** | The owner's address, which they sign in with. |
| `INSTALL_OWNER_NAME` | `Owner` | The owner's name, as the dashboard shows it. |
| `INSTALL_OWNER_PASSWORD` | **required** | The owner's first password. |

The first install prints a one-time setup token. Sending it to `POST /api/v1/users/confirm-installer` within a day confirms the owner's address, so they can sign in without a mail server. If their first sign-in after it comes from a new device, they set up a second factor there. Later sign-ins from a new device ask for it.

### First operator

| Variable | Default | What it does |
| --- | --- | --- |
| `OPERATOR_PASSWORD` | **required** for `operator create` | The first operator's password. Read only by `ianua operator create --email <address>`, and refused by `serve`, `install` and `demo`: a password left in a server's environment outlives the one run that needed it. The command makes nobody once any operator exists. |

## Database

The platform signs in to Postgres as three roles, and makes a fourth for the gateway and a fifth for the nameservers where each is deployed. Each URL must name its role and hold its password. Role names take lowercase letters, digits and underscores only.

| Variable | Default | What it does |
| --- | --- | --- |
| `DATABASE_URL` | **required** | The app's role. It owns nothing, and row-level security confines it to one tenant at a time. |
| `MIGRATION_DATABASE_URL` | **required** on the worker and for `migrate`, `install` and `operator create`; refused on `MODE=api` | The database owner. It migrates, makes the app's and the audit purge's roles with the passwords their URLs hold, and makes tenants' own schemas. A process that holds it migrates as it starts; one that does not waits until the schema is current. |
| `AUDIT_PURGE_DATABASE_URL` | Required and refused like `MIGRATION_DATABASE_URL` | The audit retention purge's own role, the only one that may remove audit records. |
| `GATEWAY_DATABASE_URL` | none; refused on `MODE=api` | The gateway's role, such as `ianua_gateway`. Set it on worker nodes, and for `migrate` and `install`, where a gateway is deployed: the migrations then make that role with the password the URL holds and its narrow grants, and open tenants' own schemas to it. The server never signs in as it. The gateway signs in with the same setting and the same value. |
| `NAMESERVER_DATABASE_URL` | none; refused on `MODE=api` | The nameservers' role, such as `ianua_nameserver`. Set it on worker nodes, and for `migrate` and `install`, where `ianua-dns` is deployed: the migrations then make that role with the password the URL holds. It reads the zones, their records, and of each claim on a name only who holds it and whether it was proved, and nothing else. The server never signs in as it. `ianua-dns` signs in with the same setting and the same value. |
| `DATABASE_MAX_CONNECTIONS` | `10` | Connection pool size, from 1 to 1000. |
| `TENANT_DB_MAX_CONNECTIONS` | `5` | Pool size for each tenant's own database, from 1 to 1000. |
| `DATABASE_ACQUIRE_TIMEOUT_SECONDS` | `5` | Longest wait for a free connection. |
| `AUDIT_PURGE_MAX_CONNECTIONS` | `2` | The purge's pool, from 1 to 100. |
| `AUDIT_REQUIRE_SEALED` | on in production | Refuse to start unless the app's role can neither change nor remove an audit record. The gateway does not read it. |
| `DATABASE_READY_POLL_SECONDS` | `3` | How often a starting process asks again whether the schema is current. |
| `TENANT_DB_RELOAD_SECONDS` | `300` | How often each node reads every tenant's database route again. The gateway does not read it; it reloads on `GATEWAY_RELOAD_SECONDS`. |

## Keys

The three keys are each exactly 32 bytes, written as 64 hex characters or as base64. `openssl rand -hex 32` makes one.

| Variable | Default | What it does |
| --- | --- | --- |
| `HMAC_SECRET` | **required** | The shared root. It keys the digests of handed-out secrets, such as API keys and codes, and the data-plane checks. The gateway holds it too, with the same value. |
| `EVENT_SIGNING_SECRET` | **required** | The control root. It keys the seals on events, live updates, the audit chain and delivery receipts, the passkey ceremonies, file links, the pairwise IDs SAML apps are sent, and the sign-in puzzles. The gateway never holds it, so it cannot forge any of them. Must not be `HMAC_SECRET`. |
| `ENCRYPTION_KEY` | **required** | The key stored secrets are sealed under now. Never lose it: what was sealed under it cannot be read without it. |
| `ENCRYPTION_KEY_ID` | `k1` | The id the current key is filed under. |
| `ENCRYPTION_RETIRED_KEYS` | empty | Earlier keys, as `id:key` pairs, comma-separated. Values sealed under them are still opened. No id twice, and none the current key's. |
| `ARGON2_MEMORY_KIB` | `65536` | Memory for one password hash. |
| `ARGON2_ITERATIONS` | `3` | Passes for one password hash. |
| `ARGON2_LANES` | `4` | Lanes for one password hash. |
| `ARGON2_MAX_CONCURRENCY` | `0` | Password hashes run at once on a node. `0` means one per CPU. It also sets how many sign-ins a node works on at once, never more than half of `DATABASE_MAX_CONNECTIONS`, so a crowd of sign-ins always leaves connections for everybody else. |
| `ARGON2_PERMIT_WAIT_MS` | `500` | How long a sign-in waits for a free place, and then for a free hash, before it is told the server is busy. |

## Bus

Events go out over a NATS bus. Without `BUS_URL` the bus lives inside the process, which only a single node (`MODE=all`) may use.

| Variable | Default | What it does |
| --- | --- | --- |
| `BUS_URL` | unset | The bus server, as `nats://`, `tls://`, `ws://` or `wss://`. It must not hold a user or password. **Required** with `MODE=api` or `worker`. |
| `BUS_TOKEN` | unset | A token to sign in to the bus with. |
| `BUS_CREDENTIALS_FILE` | unset | Or a NATS credentials file. Not both. |
| `BUS_TIMEOUT_SECONDS` | `5` | Longest one call to the bus may take. |
| `BUS_MEMORY_EVENTS` | `10000` | Events the in-process bus keeps, from 1 to 10,000,000. |

## Cache

Rate limit counts, cache versions and spent sign-in puzzles are shared through a Redis cache. Without `CACHE_URL` they live inside the process.

| Variable | Default | What it does |
| --- | --- | --- |
| `CACHE_URL` | unset | The cache server, as `redis://` or `rediss://`. It may hold a password, so it is read as a secret. **Required** with `MODE=api` or `worker`, and whenever `BUS_URL` is set. |
| `CACHE_TIMEOUT_SECONDS` | `5` | Longest one call or connection attempt to the cache may take. |
| `CACHE_MEMORY_ENTRIES` | `100000` | Entries the in-process cache holds, from 1 to 100,000,000. |
| `STORE_CACHE_LIFETIME_SECONDS` | `20` | How long a resolved caller and its access records are kept in front of the database, from 1 to 300. It is how long a revoked grant may still be served. |
| `STORE_CACHE_CALLERS` | `50000` | Resolved callers kept, from 1 to 10,000,000. |
| `STORE_CACHE_HOLDINGS` | `20000` | Holders' access records kept, from 1 to 10,000,000. |

After a connection loss, the cache client reconnects automatically with bounded,
randomized delays. A short outage does not require restarting the server or gateway.

## Namespace

Every name the platform uses on the bus server and the cache server starts with its namespace: the event subjects (`<namespace>.tenant.<id>.<event type>`), the streams (`<namespace>-events`, `<namespace>-messages`, `<namespace>-dead-letters`), the worker's consumers inside those streams, live updates, and every cache key (`<namespace>:<key>`). Two deployments with different namespaces, such as staging and production, can share one bus server and one cache server and never hear each other's events or count each other's limits. Give each its own `HMAC_SECRET` and `EVENT_SIGNING_SECRET` as well.

| Variable | Default | What it does |
| --- | --- | --- |
| `NAMESPACE` | `ianua` | What every bus and cache name starts with. 1 to 32 lower-case letters, digits and dashes, starting and ending with a letter or digit. The default keeps the names the platform has always used. The server and the gateway of one deployment must hold the same value. |

With `EMAIL_PROVIDER=none` no mail goes out, and every mail is recorded as undelivered. A sign-in from a new device, or one that looks risky in another way, then asks for the person's second factor instead of a mailed link. Someone with no factor is refused, and an administrator must send them an invitation. The one exception is the first sign-in after the install's setup token or an accepted invitation: that route already proved the person, so they set up an authenticator app there and then. `EMAIL_FROM` is still needed, for tenants that send through their own mail provider. Such a deployment also offers no mailed sign-in codes, no magic links, no password reset by email (an administrator sets the password instead), no self sign-up and no address confirmation links; an administrator lets new accounts in at once. An invitation hands its accept link to whoever sent it, to pass on to the invitee, and accepting it leaves the address unconfirmed, since no mailbox was proved; changing an address is refused. An account still waiting to confirm its address stays waiting until an administrator activates it by hand. A person whose address was never confirmed still signs in, the address left unconfirmed, and a password that expired is replaced inside the sign-in, as on every deployment. A password an administrator set can be replaced there only by someone with a second factor; anyone else is refused, and an administrator should send an invitation instead.

## Worker

A caller without a certificate that authority signed never completes the handshake. The stream sends proved custom zones and enabled platform zones, the whole catalog again whenever it changes. At most 16 streams are open at once, a handshake must finish within 5 seconds, and a call must start answering within 10.

Nested platform addresses use a separate certificate for each tenant's random root and its wildcard. The tenant may enable `readable_address` through its settings API to add `<tenant>.<organization>.<base>` and its wildcard. This defaults off, every change is audited, and public authorities publish these readable names in certificate transparency logs. A newly enabled name becomes usable after background certificate issuance and the gateway's reload. Turning the setting off stops serving the names; it cannot erase earlier transparency entries. Flat deployments do not offer readable names.

### Gateway start-up checks

Besides each value on its own, the gateway refuses to start when:

- **It holds a control plane secret.** `EVENT_SIGNING_SECRET`, `DATABASE_URL`, `MIGRATION_DATABASE_URL`, `AUDIT_PURGE_DATABASE_URL` and `CONNECTOR_CA_KEY_FILE`, or their `_FILE` forms, are refused. The gateway faces the internet, so it never holds the key that seals events or another role's login.
- **Production has no shared bus or cache.** Without `BUS_URL` the gateway hears no configuration change and shares no blocked address. Without `CACHE_URL` each gateway counts rate limits, budgets and replayed DPoP proofs on its own, so each lets the same request through. `BUS_URL` without `CACHE_URL` is refused in development too.
- **Plain HTTP in production.** The main listener always ends TLS itself in production.
- **Two listeners share a port.**
- **A wait is as long as what it waits inside.** `GATEWAY_COUNTER_TIMEOUT_MS` and `GATEWAY_APP_SESSION_CHECK_TIMEOUT_MS` must be shorter than `GATEWAY_PIPELINE_TIMEOUT_MS`. `GATEWAY_TUNNEL_RECHECK_TIMEOUT_SECONDS` must be shorter than `GATEWAY_TUNNEL_RECHECK_SECONDS`.
- **A setting nothing would read**, such as `VAULT_TOKEN` without `VAULT_ADDR`, `LOG_SINK_AUTH` without `LOG_SINK_URL`, `OTLP_SERVICE_NAME` without `OTLP_ENDPOINT`, or `API_INTERNAL_TIMEOUT_SECONDS` without `API_INTERNAL_URL`.

`ianua-dns` reads its zones from one of two places. In the cluster it reads the database, signed in as the nameservers' own role. On a host of its own, which cannot reach the database, it follows the control plane's stream over mutual TLS and holds no database login. `NAMESERVER_DATABASE_URL` picks the first and `CONTROL_PLANE_ENDPOINT` the second; one of them is required, and both together are refused.

| Variable | Default | What it does |
| --- | --- | --- |
| `NAMESERVER_DATABASE_URL` | unset | Read the database as the nameservers' role, the same value the worker holds (see [Database](#database)). The app's `DATABASE_URL` is not read. |
| `DNS_REFRESH_SECONDS` | `15` | With the database: how often the zones are read again, from 1 to 3600. A tenant's change answers within this, plus the record's own time to live. |
| `DATABASE_MAX_CONNECTIONS` | `10` | With the database: pool size, from 1 to 1000. One load runs at a time, so a pool of 2 is plenty. |
| `DATABASE_ACQUIRE_TIMEOUT_SECONDS` | `5` | With the database: longest wait for a free connection. |
| `CONTROL_PLANE_ENDPOINT` | unset | Follow the control plane's stream at this `https` address, such as `https://grpc.ianua.io:50051`. |
| `CONTROL_PLANE_SERVER_NAME` | the endpoint's host | The name the control plane's certificate is checked against. |
| `CONTROL_PLANE_CLIENT_CERT`, `CONTROL_PLANE_CLIENT_KEY`, `CONTROL_PLANE_CA_CERT` | **required** with an endpoint | Files holding this host's certificate and key, and the deployment's own authority the control plane is checked against. |

## Fixed on purpose

A few values are not settings, because changing them would break something:

- How often each worker sweep runs. Every worker must agree on it, or two would count a sweep's rounds differently and each run it.
- Format limits on input, like the longest name or slug.
- The 30-second code step of authenticator apps.
- How long a SAML sign-in request from an app waits for its answer: 10 minutes.
- How old a DPoP proof may be: 60 seconds, with 5 seconds allowed for clocks that run ahead.
- Certificate lifetimes, which the certificate authority decides.
