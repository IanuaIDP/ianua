## Schemas

The Zod schemas live in `src/schemas`, one file per form area. React Hook Form uses them through `zodResolver`.

Each file exports its schemas and the input types they give. Where the rules depend on data only known while the page runs, it exports a builder instead, such as `buildAddTenantUserSchema(passwordPolicy)`.

The sign-in schemas are builders, such as `createLoginSchema`, `createSignUpSchema` and `buildAcceptInviteSchema`. They take their error messages as an argument, so the forms can show them in the visitor's language. `useAuthValidationMessages` supplies the messages. `buildPasswordSchema(policy, message?)` takes an optional message and is in English without one.

The files are `app-sign-in`, `auth`, `auth-config`, `classification`, `cloud`, `connection`, `contact`, `credential`, `crypto`, `delegation`, `domain`, `flow`, `group`, `model-provider`, `mtls`, `oauth-client`, `password`, `reset-password`, `resource-type`, `role`, `route`, `run`, `service`, `settings`, `stream`, `stream-route`, `team-member`, `tenant`, `tenant-agent`, `tenant-api-key`, `tenant-user`, `tool` and `user-attribute`.

## Types

The shared types live in `src/types`, in camelCase, one file per area: `auth`, `tenant`, `team`, `role`, `permission`, `route`, `pipeline`, `delegation`, `tenant-agent` and more. The API's own snake_case shapes are usually declared in the matching service file, and turned into these types there.

`types/permission.ts` lists what a tenant permission can be about (`Users`, `Roles`, `Routing`, `Agents` and more) and its actions (`View`, `Create`, `Update`, `Delete`, `Manage` and more). `useTenantPermissions` checks against these.

## Build and deployment

| Path | What it does |
| --- | --- |
| `dashboard/scripts/build-icons.mjs` | Runs before `npm run build`. It remakes `src/assets/material-symbols-rounded.woff2` with only the icons the code uses, downloaded from Google's Material Symbols font service. So a build needs network. |
| `dashboard/scripts/check-messages.mjs` | `npm run check-messages`: every language file must have exactly the keys of `messages/en.json`. |
| `docker/Dockerfile.dashboard` | Builds the image in three stages (packages, build, a standalone runtime) and runs it as a non-root user on port 3000. `NEXT_PUBLIC_API_URL` is passed when building. Its ignore list is `docker/Dockerfile.dashboard.dockerignore`. |
| `deploy/helm/ianua-front` | The Helm chart for Kubernetes (`values.yaml`, `values-prod.yaml`). |
| `.github/workflows/dashboard.yml` | Runs only when something under `dashboard/` changed. It checks the messages, runs lint and the type check, and builds. On `main` it builds and pushes the image and deploys it with Helm. |
