Everything a tenant shows lives in `src/components/dashboard/tenant-detail`. The same components serve both ways into a tenant (see [Two ways into a tenant](/ianua/dashboard/overview/#two-ways-into-a-tenant)):

- **Ann's view**, for the organization's Owners and Members, at `/tenants/{tenant}/...`. These pages draw their own `TenantSidebar` (`variant="management"`).
- **Pat's view**, for the tenant's own users, at `/organizations/{org}/tenants/{tenant}/...`. The main `Sidebar` shows the tenant's navigation instead.

In both views, `useTenantPermissions()` hides or turns off the sections and actions someone may not use (see [Sessions and permissions](/ianua/dashboard/auth-and-permissions/)).

The infrastructure sections are on [Tenant infrastructure screens](/ianua/dashboard/components/tenant-infrastructure/), and the agent sections on [Tenant agent screens](/ianua/dashboard/components/tenant-agents/).

## Page shells

These are the files directly in `tenant-detail`.

| Component | File | What it does |
| --- | --- | --- |
| `TenantSidebar` | `tenant-sidebar.tsx` | The tenant's section sidebar: Overview, Users, Groups, Roles and on to Settings. It builds the items for either view, and leaves out the sections someone may not see (`filterTenantNavItemsByPermission`). |
| `TenantSettingsManagementPage` | `tenant-settings-management-page.tsx` | The tenant's settings in Ann's view, with the tabs General (with where the data lives), Sign-in, mTLS, Classification and Danger zone. Each tab is hidden without its permission: `AuthConfig`, `Mtls`, `Classification` or `TenantSettings`. |
| `TenantSettingsDetailPage` | `tenant-settings-detail-page.tsx` | The tenant's settings in Pat's view: General (with where the data lives and the Danger zone, for someone with a `TenantSettings` permission), Account, Security, Sign-in, mTLS and Classification. Opening a tab Pat may not see moves her to Account with a message saying so. |
| `TenantCryptoDetailPage` | `tenant-crypto-detail-page.tsx` | The keys area, with its own sidebar: Keys, Migration, JWKS. |
| `AgentDetailPage` | `agent-detail-page.tsx` | One agent: its header, its sidebar (Overview, Access, Approvals, Activity, Runs, Credentials) and the open section. |
| `DomainDetailPage` | `domain-detail-page.tsx` | One domain: status, the DNS steps, verify, set up TLS, transfer, delete, and its DNS records. |
| `FlowDetailPage` | `flow-detail-page.tsx` | One flow: a summary, its stages over time, and actions such as start and cancel. |
| `CreateFlowPage` | `create-flow-page.tsx` | Builds a flow: name and description, stages, and agent steps added with `AddFlowNodeModal`. Stages and steps can be dragged into a new order. |
| `PipelineDetailPage` | `pipeline-detail-page.tsx` | The page around one pipeline's `PipelineDetail`. |
| `StreamDetailPage` | `stream-detail-page.tsx` | One signal stream: where it delivers, which signals, status actions, edit, and what was delivered. |
| `RouteFormPage` | `route-form-page.tsx` | Creates or edits an HTTP route (`mode`): name, priority, path pattern, methods, hosts, pipeline, service, path rewrite and policy. |
| `ServiceFormPage` | `service-form-page.tsx` | Creates or edits a service (`mode`): an upstream address or weighted backends, DNS discovery, timeout, expected audience, health checks, sticky sessions, and "Sign-in on this app". |
| `StreamRouteFormPage` | `stream-route-form-page.tsx` | Creates or edits a TCP or UDP route (`mode`): the port it listens on, protocol, who may connect, server names (SNI), backends and timeouts. |
| `CreateRoutePage`, `EditRoutePage` | `create-route-page.tsx`, `edit-route-page.tsx` | Show `RouteFormPage` to create or to edit. |
| `CreateServicePage`, `EditServicePage` | `create-service-page.tsx`, `edit-service-page.tsx` | The same for `ServiceFormPage`. |
| `CreateStreamRoutePage`, `EditStreamRoutePage` | `create-stream-route-page.tsx`, `edit-stream-route-page.tsx` | The same for `StreamRouteFormPage`. |

In Ann's view, `src/app/(dashboard)/tenants/[tenantSlug]/page.tsx` picks the section to show from the address (`tenantSections`).

## Overview, account and security

These are in `sections/`.

| Component | File | What it does |
| --- | --- | --- |
| `TenantOverviewSection` | `tenant-overview-section.tsx` | The tenant's overview. A profile card shows the name, domain, contact email, slug and sign-in link, and a Details card the language, time zone and creation date. With the Metrics permission it also shows sign-in time, a health score, the success rate, and use by day or month. Without it, the overview shows the tenant's record and a note in place of the charts. |
| `TenantAccountSection` | `tenant-account-section.tsx` | Pat's own profile: name and email, with a verification mail that can be sent again after a wait. |
| `TenantSecuritySection` | `tenant-security-section.tsx` | Pat's own security: change the password, the second factor, passkeys and trusted devices. |
| `TenantPolicySection` | `tenant-policy-section.tsx` | The tenant's access policy: its status and where it can move next (draft, review, active, archived), its rules in order, and what happens when no rule matches. It can be changed only as a draft. |
| `PolicyRuleEditor` | `policy/policy-rule-editor.tsx` | Edits one rule: name, priority, on or off, conditions, action, and the reason for a refusal or the assurance needed. |
| `fieldContainerClassName` and others | `form-field-styles.ts` | Shared class names for form rows that repeat. |

## Custom user fields

These are in `sections/user-attributes/`.

| Component | File | What it does |
| --- | --- | --- |
| `ManageUserFields` | `manage-user-fields.tsx` | The Users page's **Manage fields** button and menu. Active fields have a show-in-list switch, Edit and Archive. Archived fields fold into their own part, with Restore and Delete. It has an empty state and a tooltip on every icon button, and opens the add, edit and delete dialogs. |
| `UserFieldRow` | `user-field-row.tsx` | One field in the menu: name, type badge, and a mark if it is sensitive. An active field has the show-in-list switch, Edit and Archive. An archived one has Restore and Delete. |
| `UserFieldIconButton` | `user-field-icon-button.tsx` | An icon button in the menu, with its tooltip. |
| `UserFieldFormModal` | `user-field-form-modal.tsx` | "Add a field", or "Edit a field" when given one. It wraps `UserAttributeForm`. |
| `DeleteUserFieldModal` | `delete-user-field-modal.tsx` | Asks "Delete field?". |
| `UserAttributeForm` | `user-attribute-form.tsx` | Defines a field. It has the field type and how it is shown, a name and help text, and limits by kind (longest text, lowest and highest number). It has choices, one per line, and switches for Required, Show in user list, Allow filtering, Allow sorting and Sensitive. Advanced settings fold away: the internal name, and who manages the field. |
| `AttributeControlField` | `attribute-control-field.tsx` | Draws the right input for a field. How it is shown is only a hint: the API checks the value by its kind. |
| `AttributeValueCell` | `attribute-value-cell.tsx` | Shows a stored value in a table: a swatch, stars, chips or formatted text. |
